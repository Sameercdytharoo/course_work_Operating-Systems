## 0:00 - 1:00 | Introduction & Architecture
**Visual**: Show your **System Architecture Diagram** (Week 1 Journal) on screen.

**Script**:
> "Hello, my name is Sameer Chaudhary Tharu, Student ID A000027591. This is my broad demonstration for the Operating Systems module coursework.
> 
> I have designed and deployed a secure, dual-system architecture. 
> As you can see in this diagram, I am using a **Headless Ubuntu Server 22.04 LTS** as my target system, isolated within a virtual network. 
> My administration workstation is my local Windows host, communicating strictly via SSH on a non-standard port 2222.
> I chose this 'Host-Client' approach to simulate a real-world cloud administration scenario where the server is remote and accessed only via secure command-line tools."

## 1:00 - 3:00 | Security Configuration Verification
**Action**: Switch to your **Terminal Window**.
**Action**: SSH into the server clearly.

**Script**:
> "I will now demonstrate the security controls I have implemented following the Principle of Least Privilege and Defense in Depth.
> First, I will connect to the server using my non-root admin account."

**Command**: `ssh -p 2222 admin_user@127.0.0.1`
*(Mention: "I am using key-based authentication. Root login is disabled.")*

**Script**:
> "To verify my security baseline, I created a unified automation tool called `manage_coursework.sh`. This ensures my configuration is consistent and auditable."

**Command**: `sudo ./scripts/manage_coursework.sh`
*(Select Option 2: Run Security Baseline Check)*
*(Wait for output)*


**Script**:
> "As you can see from the output:
> 1. The **UFW Firewall** is active and implementing a 'Default Deny' policy.
> 2. **Root Login** is explicitly disabled in SSH config.
> 3. **AppArmor** is enforcing mandatory access control profiles.
> 4. **Fail2Ban** is active to prevent brute-force attacks.
> 5. **Unattended Upgrades** are configured to install security patches automatically."

## 3:00 - 5:00 | Remote Monitoring & Administration
**Action**: Open a **NEW Terminal Window** (Keep the server window open).
**Action**: Arrange them side-by-side if possible.

**Script**:
> "A key requirement was remote monitoring without installing heavy GUI tools on the server. 
> I developed a remote monitoring script that runs on my workstation and pulls key metrics via SSH."

**Command**: `./scripts/monitor-server.sh admin_user 127.0.0.1 2222`
*(Let it run for 10-15 seconds)*

**Script**:
> "This tool gives me real-time visibility into CPU Load, Memory Usage, and Disk I/O.
> You can see the system is currently idle. 
> This approach is superior to installing a GUI on the server because it saves significant resources—crucial for potential energy savings in data centers."

*(Stop the script with Ctrl+C)*
